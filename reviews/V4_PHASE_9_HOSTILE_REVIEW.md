# Phase 9 hostile review — zero open findings

Reviewed in Debug on 2026-09-29 against disposable Access databases only. The production database and Release artifacts were not used. Phase 9's technical exit gate is complete with zero open findings. The user moved the visual review of record pages and the timeline to Phase 11; this technical sign-off does not imply visual acceptance.

## Correctness and security findings fixed

1. An unchanged database yielded different randomized `observedRevision` values for overview, history, and image reads. The viewer repeatedly restarted the same page and remained dimmed. Revisions now use a deterministic authenticated cursor for one position and UTC issuance window; ordinary page cursors remain randomized. Regression: `ObservedRevisionIsStableAcrossIndependentReadsOfTheSamePosition` and headless Chrome's stable `Live` record state.
2. The sidebar's selected record kind was overwritten by the all-kinds search parameter. The search query now keeps the chosen kind. Headless Chrome showed only two Character rows in Characters and only one Source row in Sources.
3. A slower search could replace the results of a later navigation action. A per-search generation check now discards superseded responses.
4. A deleted canon record's gallery request used active-owner resolution and could fail the whole page. The viewer now requests `image_list` with explicit deleted inclusion for that page. The deleted-owner regression passes.
5. A deleted source snapshot's cached-text request could fail the whole record page. `source_snapshot_view` now requires explicit `includeDeleted` for that content, retains byte/hash/path verification, and the typed client and viewer pass that flag only when opening a deleted snapshot. The deleted-snapshot regression and regenerated v4 contract tests pass.
6. Full-text search only checked the first 255 characters of some long records. The content filter now checks the full stored text while limiting returned previews; the deep Markdown-note regression passes.
7. A record opened with `includeDeleted=true` emitted `All`-scope relation cursors, while the viewer followed them with the default `Active` scope. Clicking “Load more notes” failed with `cursor.invalid` and replaced the page with an error. The viewer now preserves the `All` scope. Headless Chrome advanced one character's notes from 20 to 27, with no duplicate rows and a Live state.
8. Rapid continuity selections could complete out of order against one browser session. Selection requests are now serialized and stale responses cannot repaint the UI; starting another selection also invalidates pending record/image work. Chrome's rapid-switch probe ended with the picker, route, heading, and backend session on the second continuity.
9. Opening a source snapshot's generic record page exposed its `RelativeCachePath`. The field filter matched only contiguous `RelativePath`, missing `RelativeCachePath`. It now excludes every storage-path field ending in `Path`, and a regression checks that a deleted snapshot overview does not expose one. The record UI also omits the redundant `entityReference` detail because the explicit copy-reference action already supplies it. The focused four-test snapshot suite passed; headless Chrome reopened the deleted snapshot against the rebuilt Debug viewer and found cached text, no `source-cache` path, no `entityReference` detail, and a Live state.
